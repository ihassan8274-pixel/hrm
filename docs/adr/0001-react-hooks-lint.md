# ADR 0001 — منع أخطاء ترتيب الـ hooks بقاعدة ESLint

- الحالة: مقبول
- التاريخ: 2026-11-26

## السياق
ظهر خطأ إنتاجي بعد نشر القائمة الجانبية الديناميكية:

```text
Rendered more hooks than during the previous render.
```

السبب كان `useRef` و`useEffect` جديدين وُضعا بعد عوائد مبكرة في `AuthenticatedApp`، فتغيّر عدد الـ hooks بين عرض أثناء التحميل وعرض بعد اكتمال الجلسة. `tsc` لا يرى هذه القاعدة، واختبارات الوحدة لا تجعل المكوّن يمرّ بحالتَي الجلسة.

## القرار
إضافة `eslint-plugin-react-hooks` مع قاعدة `rules-of-hooks` كخطأ، وربطها بـ `npm run lint` حتى يمرّ `npm run verify` وCI بها. تُضاف قاعدة `exhaustive-deps` كتحذير لتفادي تغيير سلوك المؤقتات دون قصد.

## البدائل المرفوضة
- الاعتماد على اختبار نصّي يفحص ترتيب الأسطر فقط: هشّ ولا يغطي مكوّنات أخرى.
- إصلاح الحالة once-off دون بوابة: يسمح بتكرار الخطأ في مكوّن جديد.

## العواقب
- أي hook جديد بعد `return` يفشل قبل النشر.
- قد تحتاج مكوّنات قديمة إلى تعديل موضع الـ hooks؛ يُجرى ذلك في commit منفصل مع `npm run verify`.
